# ประเด็นที่ต้องเลือกก่อน implementation

Spec ใช้ symbolic parameters ยังไม่มี approved numeric profile ระดับ diagnostic 1.0/0.75/0.5 ไม่ใช่ controller calibration หากประเด็นใดยังไม่ตัดสิน candidate ต้อง e=1 ไม่เติม defaults เงียบ ๆ

| ประเด็น | แนวทางที่เสนอ | ทางเลือก / tradeoff | สิ่งที่ต้องให้ผู้ใช้เลือก |
| --- | --- | --- | --- |
| Timing | native pre-production decision ตาม food.tick ซึ่งลงบัญชี [food_day,day) | forward-interval persistent effort ทำ causal time interpretation ชัดขึ้น แต่ต้องออกแบบ clock/observation/persistence ใหม่ ไม่อยู่ใน v1 | ยอมรับ native accounting-only semantics หรือแยก clock design ก่อน implementation |
| Scope | closed local component; ไม่ลดเมื่อมี imports/shared/export obligations ที่ประเมินไม่ได้ | network-aware forecast เปิดโอกาสลดมากกว่า แต่ต้อง model ทุก requests/ownership/competition และ endogenous feedback | จำกัด v1 ตามนี้หรือขอ network specification ใหม่; ไม่เพิ่ม scope โดย parameter flag |
| Reserve floor | entry รักษา actual baseline binding-cap closing target และ approved stress floor; ห้ามสร้าง debt ตั้งแต่ entry | floor เป็น fixed demand-days ง่ายแต่ไม่คิด season/loss; seasonal deficit envelope ยืดหยุ่นกว่าแต่ต้องเลือก risk bounds; cap-retention รักษา baseline reserveแต่ไม่ได้พิสูจน์ว่า baseline capพอทุกshock | floor rule, units/local-accessible ownership, floor demand-day valueถ้าใช้ และเมื่อ target>cap ให้ abstain/รายงาน infeasible ตามเสนอ |
| Lookahead | ครอบคลุม low-season crossing ที่เกี่ยวข้องและเวลาชำระ debt ตามเต็ม effort ภายใต้ bounds | horizonสั้นเร็วแต่พลาด low season/repayment; horizonยาวอนุรักษนิยมและ unknownมาก จนอาจลดไม่ได้เลย; ไม่ใช้ H จากการทำให้ winter fixture ผ่าน | H เป็นวัน/จำนวน native intervals, terminal reserve requirement และ treatmentเมื่อ horizonเกินข้อมูลที่รับรองได้ |
| Demand/availability envelope | แยก current known demand กับ upper bound; imports=0, ไม่รับประกัน future child chores; stress producer-loss budget | zero future productionทุกคน conservativeมากแต่แทบ no-op; bounded loss (เช่น largest adultหาย) มี residual riskจาก multipleloss; ไม่ใช่ predictionว่าใครตาย | Δdemand bound, producer loss magnitude/duration, child future lower bound, observation-latency bound; ถ้าไม่เลือกให้ unknown/e1 |
| Minimum effort | analytic inverseจาก required production clampด้วย e_min; เริ่มจาก floorที่ผู้ใช้ยอมรับความเสี่ยง และไม่ผูกกับ diagnostic .75/.5 | e_minสูงลดได้少/transitionเล็ก; e_minต่ำลดได้มากแต่ตอบ shockได้ช้าหรือเกิด stock debt หาก modelผิด; e_min=1 คือ disabled profile | ค่า e_min∈(0,1] และ continuous vs separately specified quantization; ไม่มีค่าตัวเลขที่พิสูจน์ปลอดภัยแล้ว |
| Downward ramp | จำกัด decrease ต่อ decision; emergency increaseกลับ1ทันที | Δe_downเล็กทำ gradualแต่ยังเปลี่ยนผลยาว; ใหญ่ลดoverflowเร็วและผลจากmodelผิดมาก; inertiaที่หน่วง return1ไม่เสนอ | Δe_down และหน่วย per decision/per accounted days; กฎ stalepreviouscommand |
| Entry/re-entry hysteresis | ต้อง consecutive certified safe observations N_enter; recoveryใช้ N_reenterและ actual debt=0 | ค่าสูงลดchatterแต่พลาดsurplusช่วงสั้น; ต่ำเริ่มเร็วแต่ noise/branchchangeทำ flip-flop; observedsafeไม่ทำนายshock | N_enter,N_reenter, clearance margin และ cooldown ถ้าต้องการ; ห้าม cooldownหน่วง emergencyreturn1 |
| Recovery timing | immediate e1 ณ pre-productionเมื่อ observedfail; post-tick failสั่ง e1ที่จุดถัดไป | faster event-triggered controlต้องมี clockhookใหม่; ไม่สัญญาแก้อาหารที่ขาดแล้วระหว่างticks | ยอมรับ next-native-point latency; maximum tolerated latencyและถ้าเกินให้ stop candidate; no mid-interval compensation |
| Target debt retirement | เก็บ targetเดิมจน actualrepayment; targetลด/ capลดต้อง explicit review rule | ไม่ retireอัตโนมัติอาจ RECOVERค้างเมื่อคนตาย/demandลด; retireเร็วทำdebtหายทางตัวเลขและซ่อนfailure | target-retirement ruleเมื่อ ownership/population/capเปลี่ยน; ห้ามลบ debtเพียงเพราะค่าฟลอร์เปลี่ยน |
| Affordability/pay criterion | no worsening meals/pack funding/unpaid/unmet/per-cid real payใน projection; ไม่ชดเชยด้วยเงินใหม่ | อนุญาต paydecreaseอาจเพิ่มโอกาสลดproductionแต่เปลี่ยนobjectiveและwelfarecontract; aggregatepayไม่ปกป้องรายคน | ยืนยัน strict baseline payment-preservation หรือให้แยก economics specificationใหม่ |
| Persistence/numeric contract | statebookkeepingแยกจาก originalfood/gold; invalidversion→e1; source/digest semanticsคงเดิม | storingstateในSimจะเปลี่ยนhashschemaและsaveversion ต้องreview; epsต่อmetricต้องมีunitsไม่ยืดเพื่อให้ผ่าน | storage/versioning/restartfailclosed, rounding marginและtesttolerancesก่อน implementation |

ข้อเสนอเชิงทิศทางคือ native-accounting/closed-local/baseline-cap-retention/zero-import/strict-affordability พร้อม explicit risk envelope และ immediate-return1 ไม่ใช่ numeric profile ที่ได้รับอนุมัติ

อย่าตัดสิน H/floor/e_min/ramp/streak โดยเลือกค่าที่ผ่าน fixtures เก่า ต้องบอก operational objective, admitted risk และ resource budget ก่อนตรึงหนึ่ง profile จากนั้นรายงานผลของ profile นั้นครบทุก test รวม noop/infeasible/unsafe โดยไม่ sweep หรือเปลี่ยนค่าระหว่างรัน หากต้องเปลี่ยน profile ให้เป็น design revision พร้อมเหตุผลและคำสั่งใหม่

การตัดสินข้างต้นไม่ใช่การอนุมัติ implementation หรือ simulation อัตโนมัติ งานนี้หยุดที่ design
